## Power history and MQTT recovery

v1.4.21 includes the graph storage and Home Assistant MQTT fixes from
[PR #41](https://github.com/leaberry/ESP32C6-APsystems-ECU/pull/41).

- Optional **Power over time** graphs show individual inverters or the fleet
  over 24 hours, 3 days, 10 days and 30 days. Enable recording through
  **Menu > Energy history > Enable detailed history**. It is off by default.
- The current day stays in RAM. A nightly UTC batch saves completed days,
  reduces older detail and expires data beyond 30 days. Storage is capped at
  192 KiB, with up to 38 KiB of current-day RAM. Recent buckets follow the
  polling interval with a one-minute minimum; older data uses five-minute,
  then hourly averages. Use MQTT or Modbus with an external server for a
  permanent archive.
- Sampling now keeps the latest successful reading in each bucket and uses
  the fleet poll's start time. This fixes gaps caused by reply timing. Missing
  readings remain gaps; the firmware does not invent samples.
- Missing SPIFFS files no longer trigger false damaged-history warnings.
  Real failures include diagnostic details and an authenticated raw-file
  download. Graph controls support mobile scrolling, tap inspection,
  explicit confirmation, timeouts and retry after failed requests.
- Home Assistant MQTT closes the connection after an incomplete network
  write, preventing later packets from corrupting an unfinished message.
  Pending energy is preserved through normal reconnect recovery.
- System information shows separate Home Assistant and Domoticz MQTT states.
  Energy-recovery diagnostics identify blocked checkpoints, and MQTT state
  includes `energy_status` and `energy_error`.

The reporter confirmed that graph gaps and history warnings stopped and that
MQTT works on the corrected build. The merged code also passed a production
OTA test with graph recording enabled: 112 persistent-connection Modbus reads
over 317 seconds, eight successful readings per inverter, and preserved
settings, daily totals and seven saved graph days. That hardware test preceded
this version-only release bump. Overnight durability and physical power-loss
recovery remain unverified for the new build.

## Upgrading

- For an existing supported 8 MB OTA layout, use `ESP32C6_ECU-8MB-OTA.bin`.
- For the 4 MB USB-only layout, use its matching bundle and the documented
  application-only USB upgrade procedure. Merged images are for first installation.
- Back up settings and production history and save today's local energy
  totals before restarting. Unsaved current-day graph samples and hourly RAM
  statistics reset at reboot. Existing energy/settings backups do not include
  detailed graph files.
- The MQTT sender fix does not repair an already-corrupt retained checkpoint.
  If Solar energy remains unavailable for that reason, follow the
  [checkpoint recovery instructions](https://github.com/leaberry/ESP32C6-APsystems-ECU/blob/v1.4.21/HomeAssistant.md#reset-a-corrupt-mqtt-energy-checkpoint).
  The deliberate reset discards the MQTT cumulative baseline; do not wipe
  Home Assistant statistics or local history to resolve that blockage.

Both layouts are built and tested by GitHub Actions. Downloads include the
firmware bundles, individual images, checksums and the 8 MB debugging ELF.
Polling, radio control, daily-energy accounting, Domoticz and Modbus behavior
are unchanged. QT2 monitoring remains experimental; power limiting is unsupported.

## QT2 monitoring

v1.4.20 adds experimental APsystems QT2 monitoring through [PR #7](https://github.com/leaberry/ESP32C6-APsystems-ECU/pull/7). These are the changes since v1.4.19:

- Four PV inputs and three AC readings in the web interface, HTTP API and supported MQTT formats, with automatic Home Assistant MQTT sensor discovery.
- QT2 settings backup/restore and fleet polling integration. SunSpec uses Model 103 for individual QT2 units; AC voltage and current registers remain unavailable while their interpretation is unverified.
- Automatic diagnostic capture at **Diagnostics → Download QT2 capture**. The bounded log retains raw replies, timing, firmware, counters and radio metadata. Repeated timeouts are counted without filling the log with duplicate timeout records.
- DC current and counter scaling based on measured bench references. Energy baselines handle startup, counter resets and loss of grid frequency without adding false production.
- Support for both observed QT2 telemetry headers, `BBBB29` and `BBBB30`, while preserving length, serial, checksum and trailer validation.

QT2 output limiting and grid-profile writes remain disabled. AC readings retain unverified labels, and exported-energy accuracy still needs an independent meter comparison. These limits do not prevent experimental monitoring.

## Installation

- **8 MB OTA:** use `ESP32C6_ECU-8MB-OTA.bin` for an existing installation with the supported OTA partition layout.
- **4 MB USB-only:** use the matching 4 MB bundle and the documented USB upgrade procedure.
- Merged images are for first installation. Follow the [installation and upgrade guide](https://github.com/leaberry/ESP32C6-APsystems-ECU/blob/v1.4.20/README.md) and back up settings and production history before maintenance.

Both firmware layouts are built by GitHub Actions after the 27 Python and eight JavaScript test suites pass. The release includes firmware bundles, individual images, checksums and the 8 MB debugging ELF. Firmware and web asset cache versions are updated to 1.4.20.
